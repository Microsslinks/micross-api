## ✨ 新增功能

### 1. ledger 全类型写账（§20.1-§20.3）

| 文件 | 改动 | 影响 |
|---|---|---|
| `service/topup.go` | `CompleteTopUp` 事务内写 `event=topup` ledger | 充值金额变动可追溯 |
| `service/refund.go` | `Refund` 写 `event=refund` 负向 ledger | 退款可追溯，账实相符 |
| `service/agent_quota_grant.go` | `IssueQuotaToCustomer` 写 `event=agent_quota_grant` | 经销商发额度有据可查 |

每条 ledger 行 `balance_after` 用与 commission 同款的"行锁 SELECT"算法（task-17 §17.3 沉淀）。

### 2. 注册阶段自邀拦截（§20.4）

`model.ValidateInviterForRegistration(inviterId, email, now)` 三重门槛：
- **年龄 ≥ 24h**（防批量脚本注册→立刻互邀）
- **邮箱域名不同**（防主控账号伪装）
- **24h 邀请数 ≤ 5**（防刷单）

每个门槛一个 `errors.New` sentinel（`ErrInviterTooNew` / `ErrInviterSameEmailDomain` / `ErrInviterTooActive`），controller 端 `errors.Is` 翻译为 i18n 提示。**`admin.ResetInviter` 路径不动**——admin 信任不受风控约束。

### 3. commission 实时风控叠加（§20.5）

`service.ProcessCommission` 在 AssertNoLoss 前叠加两道拦截：
- `model.DetectInviteRing(inviterId)`：DFS 沿 inviter_id 链上溯，5 跳上限检测环（A→B→A 等）
- `model.GetUserTotalConsumeQuota(inviterId)`：SUM `logs.type=consume`，小于 5000 quota 触发

任一命中时 `finalAmount=0 + breach=true + audit log`。`amount=0` 的 breach 改写 `margin_unwired` 文案让运维识别 cost_ratio 未接入。

### 4. 风控冲销（§20.6）

`commission_records` 新增 4 字段：
- `Reversed bool indexed`
- `ReversedAt int64`
- `ReversedBy int`
- `ReverseReason varchar(255)`

`service.ReverseCommission(ctx, recordID, reason, operatorID)`：行锁 + 钱包扣回 + `commission_reverse` ledger 行 + 标 Reversed。`ErrCommissionAlreadyReversed` sentinel 让二次撤销返 HTTP 409。`operatorID=0` 标识"系统自动"（与 admin 人工区分）。

### 5. admin HTTP + 风控扫描 cron（§20.7）

新增端点：
```
GET  /admin/commission/records          分页 + 过滤（inviter_id / invitee_id / reversed / breach）
POST /admin/commission/records/:id/reverse   撤销（reason 必填）
```

新增后台任务 `StartCommissionRiskScanTask`：6h tick + 1000/批 + 7 天窗口 + `IsMasterNode` 检查 + `sync.Once` 防重入。自动撤销时 `operator_id=0` 标识"系统自动"，便于审计日志区分。

**启动时机**：`main.go:130` 启动（紧跟 `StartSubscriptionQuotaResetTask`）。

### 6. admin UI 前端（§20.8）

新增 `web/src/features/admin-commission/`：
- 列表 + 过滤 + 分页（12 列）
- 撤销对话框：reason 必填 + record 摘要预览
- 乐观刷新（撤销成功后本地替换 row，保留分页位置）
- 路由 `/admin/commission` 自动注册（ROLE.ADMIN 守卫）

新增前端文件 oxlint 0 errors / 0 warnings / tsgo -b 0 errors。

## 🛠️ 升级指南

### Docker 部署（推荐）

```bash
# 1. 拉新版本
docker pull ghcr.io/dukaworks/micross-api:v0.37.1

# 2. 停旧实例
docker compose down

# 3. 启动新实例（GORM AutoMigrate 自动处理 schema 变更）
docker compose up -d

# 4. 验证启动
docker logs micross-api 2>&1 | grep -E "(risk scan|commission_reverse|AutoMigrate)" | head -20
```

**v0.37.1 schema 变更**（GORM AutoMigrate 自动处理）：
- `commission_records` 新增 4 列（`reversed`/`reversed_at`/`reversed_by`/`reverse_reason`）

**无需手工 SQL**。`account_ledger` 表已在 v0.37.0 建好，§20.1-§20.3 仅写数据。

### 源码部署

```bash
git checkout v0.37.1
go build -o micross-api ./...
./micross-api --log-dir ./logs
```

### 数据库 Migration 注意

- **GORM AutoMigrate 自动执行**：首次启动会建 `commission_records` 4 个新列
- **大表注意**：若 `commission_records` 已有千万行，加列可能 30s-2min，建议盯启动日志
- **前向兼容**：加列是 compatible 的（`Reversed bool default false`）；回滚到 v0.37.0 代码**不需要 schema 回退**

## 🔄 回滚预案

### 软回滚（5 分钟内）

```bash
git checkout v0.37.0
go build -o micross-api ./...
./micross-api  # 重启
```

数据库**不需要回退**——v0.37.1 加列是前向兼容的。

### 硬回滚（如果 schema 不兼容）

```sql
-- 把已撤销的 commission amount 重置为 0（旧代码不知道 Reversed 字段）
UPDATE commission_records SET amount = 0 WHERE reversed = 1;

-- 重新计算钱包（确保账实相符）
UPDATE users SET aff_commission_balance = (
  SELECT COALESCE(SUM(amount), 0) FROM commission_records
  WHERE inviter_id = users.id
);
```

### cron 误判回滚（如果风控扫描误撤销）

```sql
-- 24h 内被 cron 自动撤销的全部恢复
UPDATE commission_records SET reversed = 0, reversed_at = 0, reversed_by = 0, reverse_reason = ''
WHERE reversed_by = 0 AND reversed_at > strftime('%s', 'now', '-1 day');

-- 钱包补回
UPDATE users SET aff_commission_balance = aff_commission_balance + (
  SELECT COALESCE(SUM(amount), 0) FROM commission_records
  WHERE inviter_id = users.id AND reversed = 1
);
```
