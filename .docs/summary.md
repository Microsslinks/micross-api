## 一、要做什么

### 一句话

把 NewAPI（一个单体 API 网关，全站一口价、全局分组倍率）改造成**能分层卖 API 的分销平台**（Microsslink 微观互联）。

### 卖法有几种（业务方原话）

| 卖法 | 说的什么 |
|---|---|
| 客户分层折扣 | 以官方报价为基准打折，100% / 九折 / …… / 两折 / 免费 / 定制；订阅量也能决定折扣 |
| 经销商差价 | 经销商低价进货、管理下属、自定零售折扣，还能给客户发号 |
| 邀请佣金 | 每个客户都能邀客户，按消费返佣；**不能赔本**；只进钱包、**不可提现** |
| 定向 | 同一个模型有多家供应商报价不同，给客户 55% 的时候就**不能走到 56% 的那条线** |

### 价格是怎么构成的（细节）

| 层 | 名称 | 怎么来 | 谁定 |
|---|---|---|---|---|
| L1 | 官方标价 | 模型每 100 万 token 的官网价 | 平台 |
| L2 | 采购成本 | L1 × 渠道进货折扣 | 上游谈判 |
| L3 | 批发价 | L1 × 经销商折扣 | 平台给经销商 |
| L4 | 零售价 | L1 × 客户折扣 | 经销商 / 平台给客户 |

**三条不能破的规矩**：

1. **L1 是唯一出发点**，L2 / L3 / L4 全是它的折扣派生。
2. **进货折扣 ≤ 批发折扣 ≤ 零售折扣**，哪一层击穿就是亏钱。
3. **对外只有两个词：官方价、折扣。** 内部概念（倍率、分组、quota）不进业务语言。

### 对外要回答的三个问题（判定标准）

- 客户：这次花多少钱？为什么是这个价？怎么才能更便宜？
- 经销商：我进价多少？最低能卖多少？我能赚多少？
- 运营：这单赚了吗？亏在哪里？要不要调？

> 讲不清不是文案问题，是模型问题 —— 改模型，不改文案。

**第 7 件最要紧，也最克制**：折扣是**乘进分组倍率**里的，不是另开一条计算路径 —— 这样预扣、按次计费、重试、结算、任务重算、流式扣费六处读到的必然是同一个数，不会出现"预扣按折后算、结算按原价扣"。而且：

- **总开关默认关**。关着时折扣只用于试算和保存前检查，扣费仍按官方标价，行为跟改造前一模一样。
- 折扣数据异常（读不出、非数字、超出范围）一律回退官方价并记错误日志 —— 不能让折扣子系统拖垮整条计费链路。
- 全程 `relay/` 的转发与渠道适配**零改动**。
