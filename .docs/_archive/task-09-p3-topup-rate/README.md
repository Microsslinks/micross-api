## 一、背景

P3 的"发额度"动作现在的实现（`web/src/features/dealer/` `agent-customers-panel.tsx`）是**面值 1:1**：发 100 元就从经销商自己余额扣 100 元。

但 `task-02-business-goals/03-agent-and-commission.md` §3.1 的**旧验收口径**是"发 100 元面值实扣 87.5"——按"批发折扣 / 零售折扣"折算。

**问题**：那条旧口径建立在**已废弃**的批发折扣列上（v0.22.0 起经销商拿货价 = 线路进货折扣 × 加价率，逐模型不同）；而发额度时**并不知道客户将来调用哪个模型**。所以折算比例必须由业务方给。

---

## 二、3 条候选（业务方挑）

### 候选 ① · 保持 1:1
- **账最简单、不可能算错**
- 经销商利润靠"线下向客户收"（在平台外）
- 验收口径 87.5 **不成立**
- **代码量**：0（什么都不用做）

### 候选 ② · 折扣方案上配"比例字段"
- 在 `discount_plans` 加 `topup_conversion_rate DECIMAL(6,6) NOT NULL DEFAULT 1.0`（或类似名字）
- 运营可填 0.875 → 发 100 实扣 87.5
- **当场算清、随时可改**
- **代价**：比例是估算的，**可能给多给少**

### 候选 ③ · 全额垫付 + 事后退差价
- 发额度时全额扣经销商余额
- 事后按客户实际用量 ×（零售折扣 − 进货折扣）退差价
- **最准**
- **代价**：要"每笔发放客户的用量"账户记录 + 结算，**绕不开"按哪个模型算"**，工作量最大

---

## 三、推荐

**先选 ②**，理由：
1. 业务方已在文档里写明"按批发折扣折算"的方向，② 与之最接近
2. 不需要新表（只改 `discount_plans` 加一列，三库兼容迁移）
3. 不阻塞经销商的真实业务上线（保留 1:1 默认值，业务方再调）
4. ③ 是"理论最优"，但需等客户实际用量数据才能调

如果业务方挑 ①，**本任务直接关闭**（无须改代码）。
